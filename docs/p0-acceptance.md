## 三、本轮定位并修复的真实缺陷（按错误类别）

### 命令行 / 参数



1. **引号分支不登记 token**：PowerShell 传 `"build\flint-seed.exe" --version` 时，引号内字符只入缓冲、不开启 token，

   导致 `argc` 恒为 1、`args[0]` 变成 `--version`。修复：`"` 处若不在 token 中则先登记 `args[argc++]` 再翻转引号状态。

### 词法



1. **诊断行列 qword 读**：`mov rsi,[lex_line]` 把相邻 `lex_col` 带进高 32 位，打印出 `85899345922` 这类行号。改为 32 位读取。

2. **未闭合块注释未推到 EOF**：报错后残留末字节，额外产生 `无效字符 '}'` 假错误。修复为报错同时置 `lex_pos = src_len`。

### 语法



1. `parse_prefix`**&#x20;的整数分支返回被&#x20;**`adv`**&#x20;覆盖**：`node_tok` 后直接 `adv`，`rax` 变成 `ps_cur`（Token 指针），

   父节点把 “Token” 当子节点，代码生成报 “内部错误”，且报错位置恰好落在 `+ * ;` 上。修复：先存节点指针到栈槽，`adv` 后取回。

### 代码生成 / 编码器



1. `qword`**&#x20;读 32 位字段（系统性）**：`TK_END/TK_START`、`FN_LEN`、`LV_LEN`、`FX_LEN` 被 qword 读取，

   高 32 位带出相邻字段（列号 / 参数个数 / 槽位 / 行号）。后果：Token 原文为空、arity>0 或 slot>0 的符号查不到、

   合法调用被误报 “未定义的函数”。统一改为 32 位读取。

2. `emit_imm64`**&#x20;用&#x20;**`rdi`**&#x20;传值却被&#x20;**`cb_b`**&#x20;覆盖**：立即数被写成节缓冲指针（表现为 `mov rax,0x14fac0`）。修复：入口 `push rdi`，编码 `48 B8` 后 `pop rax`。

3. `cb_pad`**&#x20;用&#x20;**`rdi`**&#x20;计数却被&#x20;**`cb_b`**&#x20;覆盖**：循环变量变成指针，潜在巨量写。修复：计数落栈槽。

4. `xor eax,eax`**&#x20;被逐字节发射成&#x20;**`00 C0`（7 处）：`xor eax,eax` 后直接 `cb_b` 写的是 0x00，再补 0xC0，实际生成 `add al,al`。

   修复：改为发射 `0x31` 与 `0xC0`。

5. `print`**&#x20;实参方向反了**：栈机路径写出 `mov rax,rcx`（`48 89 C8`），把右操作数残留值送进 `print`，打印 `12` 而不是 `14`。

   桩约定是 “值在 rcx”，修复为 `mov rcx,rax`（`48 89 C1`）。

### 链接 / PE / 数据



1. **Token 名称表存绝对地址**：`dq n_eof, ...` 在无重定位的镜像里是无效地址，`--tokens` 一访问即 `0xC0000005`。

   修复：改存 “相对表基址的 32 位偏移”，运行时 `lea rdi,[table+off]`。

2. `add rdi,rax`**&#x20;先加后装载**：dump 逻辑里先 `add rdi, rax` 再加表基址，指针变成垃圾。改为单条 `lea rdi,[rdx+rax]`。

### 诊断输出



1. `diag_tok`**&#x20;的&#x20;**`TK_START`**&#x20;qword 读**：字节偏移被 `TK_END` 污染成天文数字，`find_line_start` 越界读取直接崩溃。

   修复：32 位读取；这也是 “语法 / 语义错误一打印就崩” 的根因。

2. `print_snippet`**&#x20;栈槽宽窄混用**：`行号`/`插入符宽度` 按 qword 读，带出相邻字段，插入符被钳到 160 列。

   修复：按 dword 读取。

3. `diag_name`**&#x20;少一个空格**：输出 `未定义的函数'foo'`，改为 `未定义的函数 'foo'`。

## 四、已知限制（阶段零接受，阶段一之后处理）



* 产物单节 RWX、无 ASLR/NX、`RELOCS_STRIPPED`；强加固环境不可用（阶段七解决）。

* 生成物依赖 kernel32（`GetStdHandle/WriteFile/ExitProcess`）；裸机 / 内核场景需阶段八自实现。

* 无调试信息与行号映射；崩溃不能回源（阶段九）。

* 表达式全部走栈、无寄存器分配；深表达式栈占用线性增长（阶段六）。

* 符号表为链表；函数 / 局部数量大时查找退化（阶段四 / 六换哈希）。

* 错误恢复只保证不崩溃与继续扫描，不保证错误 AST 可用于生成。

* 语言正式名称未定，当前 `Flint` 为代号；改名只影响 `build.ps1`、文件后缀与文档标题。

## 五、验收结论

阶段零的三个硬指标均已达成：



1. 纯 NASM 汇编可构建出可加载运行的种子编译器（无 C/Rust/Python 宿主、无外部链接器）。

2. 种子编译器可把 `.fl` 源码编译成**不依赖运行时、可直接运行的 PE32+**，算术 / 变量 / 函数 / 参数 / 内建 `print` 全链路正确。

3. 诊断系统达到 “路径：行: 列 + 源码片段 + 插入符” 的精度，词法 / 语法 / 语义错误均能在一次编译中定位且不崩溃。
